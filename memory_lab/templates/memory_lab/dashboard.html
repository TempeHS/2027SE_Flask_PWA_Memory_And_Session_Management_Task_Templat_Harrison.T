How to read this dashboard (and what the buttons do)

This dashboard measures the School Canteen app while it runs. The top half is about memory (on the server and in the browser). The bottom half is about sessions (how the server remembers each customer). Everything updates once a second.

  • New tab / New window (same session): opens the menu again in this browser. It shares your cookies, so it joins your session: look for a new tab ID on your session tile and in Open tabs. A web page cannot open a private window, so to see a new session open the app in a private/incognito window or another browser yourself.
  • +10 / +50 customers: adds that many customers, each on their own device, so each gets their own session. Each one views the menu, adds 1 to 3 items and about half sign in, then they leave. Click it again to add more on top. These are real requests through your code, so watch what your code does with all those sessions: does the memory keep them forever?
  • Reset server: deletes every session and clears every cache, so you can start an experiment again. Saving a .py file also restarts the server.
  • Clear browser storage: deletes this site's localStorage, Cache API caches and service worker.

Key numbers

What do these numbers mean?
Python heap
The memory used by every Python object in the server right now (measured with the standard library module tracemalloc). Peak is the most it has been.
Allocated by your code
The part of the Python heap created by lines in your files (main.py, session_store.py, database_manager.py and the templates). This is the number your changes affect.
Process memory (RSS)
All the memory the operating system has given the server, including Python itself and Flask. It is much bigger than the heap and rarely goes down, because Python keeps freed memory to reuse later.
Server sessions
The number of entries in your SESSIONS dictionary: one for every browser that has visited and not expired.
Open tabs
Browser tabs showing the app that reported in during the last 8 seconds, and the total number of DOM nodes (HTML elements) in them.
Browser storage
The browser's own estimate of the storage this site uses (localStorage, Cache API and more). Browsers add padding for files from other websites, so treat it as a rough guide.

Server memory

What does this show?

The last 3 minutes of server memory. Blue is the whole Python heap. Red is the part allocated by your code.

  • A jump when customers arrive is normal: each one needs a session.
  • A line that keeps climbing while nobody new arrives is a memory leak: something keeps growing and is never released.
  • A line that drops means memory was freed, for example when sessions expire.

Client memory

What does this show?

The last 3 minutes in the browser. These are counts, not bytes.

  • Purple: DOM nodes in all open app tabs. Every HTML element uses memory in the tab.
  • Orange: responses saved in the Cache API by the service worker. They stay on the device until deleted.
  • Green: keys in localStorage. They stay on the device until deleted, and every tab shares them.

If a line climbs while you are not doing anything, the client code has a leak.

Server sessions 0

What does each tile show?

Each tile is one entry in your SESSIONS dictionary: one customer's browser. The tile with the blue border is your browser. Grey tiles are simulated customers. They have already left, so their session is only still there if your code has not removed it.

  • Colour and label: a one-way hash of the session ID. The real ID is never shown because anyone who knows it can take over the session. The badge in the corner of each app tab has the same colour.
  • Size: the memory this session's data uses on the server.
  • ID strength: roughly how many guesses an attacker needs, in bits. Every extra bit doubles it. 128 bits or more is safe.
  • Age and Idle: how long since the session was created and since it was last used. The orange bar fills up as the session gets close to expiring, and the tile fades.
  • Tabs: open tabs using this session.
  • keys: what is stored in the session.

Where is server memory going?

What does this show?

The lines of your code that created memory that is still in use. Live memory is how much, and Blocks is how many separate pieces. Lines run once at start-up (like app = Flask(__name__)) are a normal one-off cost. A line whose memory keeps growing is holding on to data it does not need.

Module-level data

What does this show?

Variables defined at the top level of your Python files, such as SESSIONS and REQUEST_LOG. They are created once, shared by every user and live until the server stops. deque (max 100) means the collection is bounded: it can never hold more than 100 items.

Caches

What does this show?

Functions using @lru_cache. A hit reused a stored result instead of running the function again. A miss had to run it. Entries shows how many results are stored and the maximum allowed (∞ means unbounded).

Open tabs

What does this show?

Every open tab showing the app. The tab ID is kept in sessionStorage, which is separate for each tab. The session comes from the cookie, which every tab in the same browser shares. DOM nodes shows the count and how much it has grown since the page loaded. JS heap is only reported by Chromium browsers and updates slowly.

Cookies set by the server

What do the flags mean?
  • HttpOnly: JavaScript cannot read it.
  • Secure: only sent over HTTPS.
  • SameSite: not sent with requests started by other websites.
  • Expires: the browser deletes it after a set time.

Browser storage for this site

What does this show?

Storage that every tab of this site shares and that stays on the device after the tabs close. localStorage holds text saved by app.js. The Cache API holds responses saved by the service worker. "Not static" entries are pages or live data that should not have been cached.
